# 三 Bot 合并 · 交互图（单人使用版）

> 前提：**全部只有你自己用** → 不需要多租户角色系统，权限可以简化成"一个 owner 白名单"，
> `docker.sock` 直接挂进主进程的风险也可以接受（可选加一层只读 socket proxy 当保险）。
> 设计稿，未改动任何代码。配套说明见 [merge-design](three-bots-merge-design.md)。

**一句话原则：模块 = 命名空间；命名空间由"当前所处的位置"决定，而不是靠命令前缀。**

三个模块共用**同一条面板消息**：点按钮就地编辑（`edit_message_text`），不刷屏；
发命令（`/start`、`/d_list`…）则新发一条到最底部并删掉旧面板，保证更新一定落在视线里。
`🏠 返回` 永远在角落，面包屑 `🏠 › 🐳` 永远可见 —— 这是三个模块能和平共处的关键。

## 图 3 · 4 个冲突命令的消歧规则

三边命令取并集后**只有 4 个真冲突**，其余（`/upgrade` `/prune` `/refresh` `/info` `/addkey` `/keys` `/clear` `/id`）
本来就不重名，**原样保留，零学习成本**。

| 输入 | 无活动模块 | 🐳 Docker 中 | 🎬 LitePan 中 | 🤖 Cline 中 |
|---|---|---|---|---|
| `/start` | 首页总览 | 首页总览 | 首页总览 | 首页总览 |
| `/help` | 合并帮助（只渲染可见章节） | ← 同 | ← 同 | ← 同 |
| `/status` | **首页总览** | 容器实时状态 | 规则 / 盘状态 | 额度面板 |
| `/list` | Docker 项目列表 | 项目列表 | 规则列表 | Docker 项目列表 |

需要在任意位置显式指定时，用永久别名：`/d_status`、`/p_status`、`/c_status`、`/d_list`。

## 图 5 · 单人部署形态

```
        ┌────────────────────────────────┐        ┌─────────────────────────┐
        │   tg-hub 容器（非 root, 只读根）│  HTTP  │  docker-socket-proxy     │
        │  ├ 🐳 docker  模块 ────────────┼───────►│  只放行 ps / pull / up / │
        │  ├ 🎬 litepan 模块             │        │  images / inspect 等端点 │
        │  ├ 🤖 cline    模块             │        └────────────┬────────────┘
        │  ├ 路由 / 面板 / 权限 / 任务中心│                     │
        │  └ data/  config.json           │                     ▼
        │         litepan-users.json      │            /var/run/docker.sock
        │         logs/audit.log          │
        └───────────────┬────────────────┘
                        │
                        ▼
                 t.me/你的bot   ← 一个会话，三个模块，一个命令菜单
```

* 单人使用：图 5 里的 socket-proxy **可以先不要**，直接挂 `docker.sock` 也能接受（省一层部署）；
  想要零成本的保险再补上。
* 三份配置合成一份 `data/`：`config.json`（含 Cline Key）+ `litepan-users.json` + `logs/audit.log`，
  统一原子写入、统一 600 权限、统一脱敏（LitePan 管理员密码 / Cline API Key / Docker 输出全部走同一层）。
* 命令菜单用 `setMyCommands` 一次下发；LitePan 的动态规则命令**限额 ≤30 条**，超出的规则进内联键盘分页
  （Telegram 全局限 100 条，三个模块共享，必须提前分配额度）。
